# [AI 지시문] 위키 증분 갱신

코드가 변경되어 일부 위키 문서가 낡았다(stale). 너의 임무는 stale 문서만
최소로 고치는 것이다. `wiki/conventions.md`의 규칙을 따르라.

## 입력

- `python3 <툴킷경로>/cw.py update .` 의 출력 — stale 문서 목록과
  각 문서를 낡게 만든 변경 파일 목록. (실행되어 있지 않으면 직접 실행하라)

## 절차 (stale 문서마다 반복)

1. 기준 커밋을 확인하라: 문서 frontmatter의 `validated_at`.
2. 변경 내용을 보라: `git diff <validated_at>..HEAD -- <변경된 파일들>`
3. 문서를 읽고 판정하라:
   - **변경이 문서 내용과 무관** (내부 구현만 바뀜) → 문서 수정 없이
     `validated_at`만 현재 커밋으로 올려라.
   - **문서의 주장이 낡음** → 해당 문장만 고쳐라. 문서를 처음부터
     다시 쓰지 마라.
   - **문서가 인용한 심볼이 삭제/이동됨** → anchor를 새 위치로 고치거나,
     내용 자체가 사라졌으면 해당 문장을 삭제하라.
4. 고친 문서의 `validated_at`을 현재 커밋으로 올려라.

## 주의

- `<!-- human -->` 표시가 있는 섹션은 절대 수정하지 마라.
  낡았다고 판단되면 수정 대신 그 아래에
  `> ⚠️ AI 검토: 이 내용은 <커밋> 변경과 충돌할 수 있음` 을 추가하라.
- `wiki/files/`는 건드리지 마라 (도구가 이미 재생성했다).
- diff에 없는 내용을 상상해서 추가하지 마라. 갱신은 뺄셈에 가깝다.
- 시그니처는 그대로인데 동작만 바뀐 경우가 가장 위험하다.
  diff를 실제로 읽고 동작 변화 여부를 판단하라. 판단이 안 서면
  해당 주장을 confirmed에서 inferred로 강등하라.

## 마무리

1. `python3 <툴킷경로>/cw.py lint .` → 에러 0까지 수정
2. `python3 <툴킷경로>/cw.py update --mark-done .`
3. 사람에게 보고: 고친 문서, validated_at만 올린 문서, 강등한 주장 목록.
